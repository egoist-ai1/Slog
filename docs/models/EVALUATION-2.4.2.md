# Egoist Voice 2.4.2: текущая модель, оптимизация и ресурсы

На компьютере установлена и запущена2.4.2. Обе модели готовы. Сохранены Windows-default микрофон, ручная пауза и13 остальных свойств настройки диктовки. Используется прежняя пара GigaAMv3 plainRNNT INT8 для слов + E2ERNNT INT8 для пунктуации/регистра, greedyCPU4 на каждый последовательный этап. Восемь файлов весов650090519B и nativeCAPI/ONNX Runtime сохранены. [Релиз](https://github.com/egoist-ai1/EgoistVoice/releases/tag/v2.4.2).

## Фактическая работа в фоне

20 снимков за45.23s; во всех техническое состояние idle-or-completed. Машина:16 логическихCPU,31.19GiB физической RAM. Измеряется точный установленный процесс, без записи тестового микрофона.

Resident и private описывают разные стороны одной памяти; их нельзя складывать. Resident занимает примерно3.39% физической RAM. ASR работает на CPU; GPU обслуживает интерфейс. Это конечное наблюдение, не гарантия постоянных0%GPU/CPU или работы без любого сбоя.

Предыдущий2.4.1 снимок был917.5MB resident/842.8MB private. Нынешний процесс уже использовался для диктовки; состояние ONNX-буферов, длительности записей и внешняя нагрузка отличаются. **Снижение постоянной RAM не установлено**; нынешние цифры выше предыдущего снимка, и причинный процент между ними не заявляется. Основной расход связан с двумя готовыми распознавателями и рабочими ONNX-буферами. Сохранение их готовности позволяет избежать загрузки моделей перед каждой диктовкой.

## Что действительно улучшено

- Короткая запись до35s передаёт исходный полный float-массив двум последовательным этапам. Одна копия20s PCM ранее стоила1280000B; теперь она не создаётся. Срезы с ненулевым offset/частичной длиной копируются по прежним точным границам.
- NativeResult читается один раз вместо повторного преобразования токенов, времён и текста.
- Очередь держит completion barrier, а typed result принадлежит вызывающему. Доказано освобождение большого результата при открытой очереди. Для обычной memory-диктовки finallyCancel уже освобождал прежний tail; её постоянная idle-утечка не установлена.
- Отключённые сигналы не создают ненужные WAV-буферы/players при запуске и обновлении настроек. Включённые сигналы и явный preview сохраняют поведение.

На настоящем source-bound сервисе публичный11.35s memory-вызов выделял в C# медианно783536B раньше и42052B теперь в обоих завершённых порядках. Снижение около94.6% относится к временным managed-выделениям этого вызова. Весам моделей и постоянной памяти процесса эта цифра не соответствует. Для файлового/длинного пути выигрыш меньше; точные значения сохранены в evidence.

## Скорость и точность

Два порядка, по два повтора короткой11.35s и составной45.4s публичной записи, memory/file:16 пар результатов old/new совпали по SHA256. PCM не мутировался; три boundary/alias случая на каждом payload совпали. Дополнительно фактический установленный CLI дал прежний accepted output. Это проверка регрессии, без нового личного WER или обещания прироста5–10%.

В обратном порядке медианы warm-short memory old294.0/new317.4ms, file old355.2/new331.8ms; long-memory old1465.3/new1425.4ms, file old1412.4/new1405.0ms. Первый порядок показывал более медленную новую сборку, а обратный не воспроизвёл устойчивого замедления по всем путям. При изменяющейся внешней нагрузке причинный прирост скорости не заявляется. Это время сервиса без доставки текста и реакции на кнопку. ДополнительныйABBA остановлен по защитному4GiB global-headroom guard; не включён в завершённые сравнения.

Непосредственно перед финальными публикациями проведеныFull1153,Compact1146+7 ожидаемых Full-only skips, WindowsCI1153. Три новых regressions падали на прежнем source. Два первых cloudCI отказали в старых реальных timer-budget тестах; принудительныйGC и timer-проверки изолированы от остальных коллекций, исходные временные ограничения/assertions сохранены. ФинальныйCI37035534178/job110932687778 проходит.

## Почему не снижены потоки и ONNX-кэш

Arena-off на прежнем native уменьшал resident примерно на110MB после80 публичных клипов, сохраняя все raw/composed outputs. Но p95 ухудшался39% и77% при смене порядка. Два потока существенно замедляли декодирование при ничтожной разнице памяти. Оба режима отклонены. Объединение похожих по размеру энкодеров невозможно: различаются все548 проверенных тензоров. Эти опыты не входят в установленную конфигурацию.
